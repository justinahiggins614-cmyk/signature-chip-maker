Data & Methodology

The Signature Computer Chip Maker and Archive is an archive of original Signature-line chip designs — its own invented chip concepts. There is no real manufacturer branding or part numbers anywhere on the site.

1. How designs are stored

Designs are stored as compact rows in 200-per-file chunks: data/chunks/cNNNNN.json.gz, each row {id, family, era, seed, name}. The data/index/chips.search.json.gz index holds one row per design [id, name, family, era]; the Finder searches this index. Nothing is invented at search time — the Finder only returns archived rows.

The full design record is not stored: it is rendered deterministically in the browser by engine.js from the design's seed (xmur3 + mulberry32 PRNG). Same family + seed + engine version ⇒ byte-identical record, forever. A per-design SHA-256 content hash is published in data/index/chips.hashes.json.gz; the on-page Verify design button recomputes it locally.

2. The Chip Record Standard

Every design renders a machine-readable canonical record — schema JAH-CHIP-RECORD/1.0 (see schema/chip.schema.json). It carries:

  • Unit-labeled specs — every numeric value carries an explicit SI unit (GHz, W, mm², V, mm, nm-class, bits, ns) and a value kind: GENERATED_TARGET (design target), SIMULATED, or MEASURED.
  • Pin-group map — functional groups with per-group IDs, purpose, and voltage domain. It is labeled NOT a fabrication pinout: real per-net layout assignments require actual EDA work.
  • Block diagram — a generated SVG illustration with version and hash, synced with the block list. It is a block diagram, never a schematic, netlist, or layout. No CAD/HDL/GDS artifacts exist for seeded designs.
  • Lineage — parent ID for remixes/variants (parents are never mutated); standalone originals carry null.
  • Canonical URL — refresh-safe deep link ?chip=JAH-CHIP-######; per-record canonical link tag.

3. Completeness ladder (honest statuses)

"Fully planned, drawn and specified" is measured on a ladder — a design may never be marked at a level without the evidence for it. Design, simulation, manufacturing, and test are separate states:

Design statusMeaning
CONCEPTConceptual design — idea, architecture, target specs. Not fabrication-ready. (All seeded designs.)
PLANNEDPlanned feature set and block partitioning documented.
SPECIFIEDFull written specification with units and interfaces.
LOGIC-DESIGNEDRTL/logic design exists (requires HDL artifact on file).
SCHEMATICSchematic capture exists (requires schematic artifact on file).
LAYOUT-DESIGNEDPhysical layout exists (requires layout artifact on file).
PROTOTYPEPhysical prototype built.
MANUFACTUREDVolume manufacturing. Never claimed without manufacturing evidence.

Separately: sim_status is NOT_SIMULATED unless a simulator name, version, inputs, and result hash are on file (see schema/simulation-record.schema.json); test_status is NOT_TESTED unless test evidence is on file.

4. Value honesty

Every numeric spec on a seeded record is a generated design target, never a measurement. TARGET / SIMULATED / MEASURED values are never collapsed into one number. The archive contains no invented test data, no invented manufacturing evidence, and no invented simulation runs.

5. Permanent IDs

Design IDs JAH-CHIP-###### are permanent: never reused, never changed. If a record were ever withdrawn, a tombstone with the ID and the withdrawal reason would remain. Archive IDs JAH-CHIP-REPORT-YYYYMMDD-#### identify filed problem reports.

6. Creation modes

Every design carries a creation mode: SIGNATURE-GENERATED (rendered by the Signature generator), USER-CREATED (made on-page by a visitor), SOURCE-DERIVED (derived from a cited source, provenance preserved), IMPORTED, or REMIXED (with a parent chip ID). All seeded archive designs are SIGNATURE-GENERATED.

7. Corrections

Use Report design problem on any record. Reports carry an ID and a category and are kept per record; historical records are never silently rewritten — corrections become new record versions, with the old spec preserved and superseded versions marked.

8. What the archive does NOT claim

Engineering disclaimer. These are generated design specifications — design-only concepts. They are not safety-certified, not manufacturable as-is, and not electrically compliant until real verification. High-voltage / high-power concepts require professional review. The archive is a design record system, not a semiconductor marketplace.

9. Authoritative sources

  • chip-archive-manifest.json — the single authoritative source for counts and versions (homepage, Finder, archive pages, API, and sitemap all read it).
  • api.json — API summary with health block.
  • ai-manifest.json, llms.txt — AI agent instructions.
  • schema/ — formal JSON Schemas for records, families, pin groups, simulations, manifests, search results.
